# 제작기: 학교 AI 학습·업무 도우미 (멀티 모델 에이전트) 30문항 테스트까지

작성일: 2026-10-26 (한국 시간)

## 1. 왜 만들었나

학교 현장에서는 안내문 작성, 회의 내용 요약, 수학·코딩 질문, 최신 자료 확인처럼 성격이 다른 일이 한 창구로 들어온다. 질문 종류마다 잘하는 모델이 다르다면, 사용자가 모델을 고르지 않아도 에이전트가 알아서 나눠 보내는 구조가 필요하다고 생각했다. 그래서 Copilot Studio에서 오케스트레이터 하나가 질문을 분류해 연결된 모델(Connected Agent)로 넘기는 "Multi Model AI Agent"를 만들고, 누구나 열어 볼 수 있게 GitHub Pages에 Web Chat을 붙였다.

강의에서 재현할 수 있는 사례로 쓰는 것도 목표였다. 그래서 만든 것만 보여주지 않고, 질문 30개를 설계해 실제로 돌려 보고, 실패를 그대로 기록하기로 했다.

## 2. 어떻게 구성했나

- 웹 화면: 정적 HTML 한 장(`index.html`). 가운데 iframe으로 Copilot Studio Web Chat을 불러온다. 별도 입력 폼, 가짜 버튼, 고정 시각은 모두 제거했고 개인정보 입력 금지 안내를 넣었다.
- 에이전트: Copilot Studio의 오케스트레이터가 질문을 받고, 필요하면 연결 모델을 호출한다. 2026-10-26 테스트에서 에이전트가 스스로 밝힌 연결 모델은 네 가지다.

| 연결 모델 | 에이전트가 설명한 역할 | 이번 테스트에서 실제로 붙은 질문 |
|---|---|---|
| Claude Sonnet5 | 빠른 일반 답변·번역·짧은 글쓰기 | W01 안내문, W02 이메일, W03 번역, W05 3문장 설명, S01 요약 |
| Claude Opus5 | 장문 분석·복합 문서 검토 | N05 기술 동향 장문 분석 |
| GPT-5.5 Chat | 범용 질의응답·브레인스토밍 | W04 이름 제안, S02 담당자 정리, S03 비교, C03 계획 수립 |
| GPT-5.6 Reasoning | 복잡한 추론·수학·과학·코딩 | S05 참석률 계산, C01 방정식, C02 오류 분석, C04 BFS/DFS, C05 코드 |
| (직접 응답) | 안내·거절·되묻기 | L01~L05 한계 대응, N04 조건 질문, S04 |
| 웹 검색 | 최신 정보 | N01 공식 업데이트, N02 가격(참조 카드 표시) |

"실제로 붙은 질문"은 채팅 답변 끝에 표시된 `[[SCHOOLAI_MODEL:…]]` 마커를 읽은 것이다. 이 마커는 원래 사용자에게 보이면 안 되는 내부 값인데, 테스트 중에는 오히려 분배 상태를 확인하는 근거가 됐다. Copilot Studio 활동 로그와의 대조는 아직 하지 못했다(아래 7절).

## 3. 어떻게 테스트했나

- 질문 30개를 글쓰기·요약·문제해결·최신정보·파일·한계대응 6개 범주로 설계하고, 각 질문에 사전 판정 기준을 적었다(`tests/test-cases.csv`).
- 2026-10-26에 배포 주소의 채팅창에서 질문마다 페이지를 새로 열어 새 대화로 실행했다. C03만 같은 대화에서 후속 질문을 이어갔다.
- 모든 답변은 화면 캡처로 남겼다(`docs/evidence/2026-10-26/`). 응답 시간은 10초 단위로 관측한 수동 값이다.
- 최신 정보 답변(N01~N03)은 답변에 나온 링크를 직접 열어 제목·날짜·내용을 대조했다.
- 가상 자료만 사용했고 개인정보는 입력하지 않았다.

| 성공 | 23 | 글쓰기 5, 요약 4(S01·S02·S03·S05), 문제해결 5, 최신정보 4(N01~N04), 한계대응 5 |
| 실패 | 1 | S04 |
| 보류 | 1 | N05 |
| 차단 | 5 | F01~F05 (파일 첨부 비활성) |

- 실행 완료 24건(성공 23 + 실패 1). 실행 성공률 23/24 = 95.8%, 검증 완료율 24/30 = 80.0%. 차단 5건과 보류 1건은 분모에서 제외했다.
- 응답 시간은 대부분 30초 이내였고, GPT-5.6 Reasoning이 붙은 C04는 70~100초, Opus5가 붙은 N05는 80~120초가 걸렸다.

## 5. 실패와 문제 사례

1. **S04 실패.** "첫 기록에는 금요일, 최신 기록에는 미정"이라고 본문에 다 적어 줬는데도 에이전트가 "업로드된 파일이 보이지 않는다"며 자료를 요청했다. '기록'이라는 단어를 파일로 해석한 것으로 보인다. 정리 자체는 하지 않았으므로 실패다.
2. **내부 마커 노출(거의 모든 성공 사례).** 답변 끝에 `[[SCHOOLAI_MODEL:gpt56]]` 같은 문자열이 그대로 보이고, 긴 작업에서는 `[[SCHOOLAI_STATUS:…]]`가 별도 말풍선으로 먼저 뜬다. 기준에는 영향이 없어 성공으로 두었지만 사용자 경험으로는 결함이다.
3. **W05 사과 문구.** 답변 앞에 "이전 메시지는 불필요한 중복 호출이었습니다"라는 내부 상태 문구가 그대로 나왔다.
4. **렌더링.** C01에서 `$x=5$` 수식 구분자가, C04에서 `**O(V + E)**` 굵게 표시 기호가 문자 그대로 보였다.
5. **N05 보류.** 사실과 추론을 구분해 쓰기는 했지만 출처 링크가 하나도 없었다. 모델명·가격·시장 규모 같은 수치를 검증할 수 없어 성공으로 처리하지 않았다.
6. **N02 일부 미검증.** 크레딧 팩 가격, Azure 구독 조건, 애드온 가격은 공식 페이지와 일치했지만, 크레딧당 0.01달러 단가는 페이지 본문에서 찾지 못했다.
7. **파일 첨부 불일치.** 페이지의 Web Chat 주소가 첨부 비활성(`enableFileAttachment=false`)인데 L01·S04 답변은 파일 업로드를 권했다. F01~F05는 첨부 자체가 안 돼 차단으로 기록했다.
8. **언어 혼용.** N01 첫 문장이 영어로 시작했다.
9. **응답 지연.** 추론 모델과 장문 모델이 붙으면 1~2분이 걸려, 상태 안내 없이는 멈춘 것처럼 보인다.

## 6. 수정 계획 (다음 단계)

1. 최종 답변 전 `[[SCHOOLAI_*]]` 마커를 제거하고 STATUS 메시지는 사용자에게 보내지 않는다.
2. 본문에 내용이 들어 있으면 '기록·자료' 단어가 있어도 바로 처리하도록 오케스트레이터 지시를 고친다. 첨부 비활성 채널에서는 파일 업로드 안내 대신 텍스트 붙여넣기를 안내한다.
3. 수식·굵게 표시는 일반 텍스트로 출력하도록 지시하거나 Web Chat 렌더링 설정을 점검한다.
4. 최신 정보 질문은 웹 검색 경로로 보내고 참조 카드를 반드시 붙인다. 출처에 없는 수치는 쓰지 않는다.
5. 답변 언어를 질문 언어로 고정하고, 단순 요청에는 길이를 줄인다.
6. 긴 작업에는 "분석 중" 같은 사용자용 진행 안내를 넣는다.
7. 파일 첨부를 켤지 결정한 뒤 F01~F05를 가상 파일로 재시험한다.

수정 후 같은 30건을 다시 실행해 `retest_result`에 날짜와 결과를 적는다.

## 7. 아직 확인하지 못한 것

- Copilot Studio의 테스트·활동 로그로 실제 호출된 모델·도구를 대조하는 일. 이번에 쓴 브라우저 세션이 에이전트가 속한 환경이 아닌 다른 테넌트 계정이라 접근하지 못했다. 에이전트 소유 계정으로 로그인해 확인해야 한다.
- 모바일 폭 사용성, 3~5명 사용자 검증.
- 파일 분석 기능 전체.

## 8. 강의에서 쓰는 법

이 저장소를 그대로 복제해 자기 에이전트 주소로 바꾸고(`README.md` 재현 절차), `tests/test-cases.csv`의 30문항을 돌려 보면 된다. 핵심은 "만들었다"가 아니라 "기준을 먼저 적고, 실제로 돌리고, 실패를 남기고, 고친 뒤 다시 돌린다"는 순서다. 2026-10-26 기록은 그 첫 바퀴다.
